# План: локальная авторизация и экспорт в Telegram / ВКонтакте

Статус: **черновик плана**. Реализация кода не начата.

## Цели (порядок важности)

1. **Цель 1 — Telegram (сейчас).** Авторизация в Telegram и публикация работ **от имени пользователя** (личного аккаунта, НЕ бота): отправка контакту из списка, в «Избранное» (Saved Messages), публикация в свою группу/канал.
2. **Цель 2 — ВКонтакте (потом).** Авторизация через браузер с автоматическим открытием, перехват токена после входа и вставка его в приложение. Публикация фото/видео на стену группы или в личные сообщения.

## Общие принципы

- **Полностью локально, без деплоя.** Никакого webhook-сервера, хостинга или публичного URL. Все вызовы — исходящие HTTPS-запросы к API Telegram/VK с локальной машины.
- **Авторизация — отдельной кнопкой**, по образцу карточек CLI-интеграций в `ai_settings.html` / `ai-settings.js` (`/api/ai/cli-integrations`).
- **Секреты шифруются** так, чтобы другой локальный пользователь Windows не мог их вытащить из файлов приложения.
- Экспортируются **image/video** (работы из медиатеки), не воркфлоу.

## Цель 1: Telegram

### Почему не Bot API
Bot API (`t.me/BotFather` + токен бота) позволяет действовать только **от имени бота**. Пользователю нужна публикация от своего аккаунта → Bot API не подходит.

### Подход: MTProto (Telethon)
Для работы от имени личного аккаунта используется **MTProto-клиент**:

- Библиотека: **Telethon** (`pip install telethon`, уже проверяется в venv; в `pyproject.toml` пока нет — добавить).
- Нужен `api_id` + `api_hash` — выдаются один раз на `my.telegram.org` под аккаунтом пользователя (локальная регистрация «приложения», без деплоя).
- Авторизация интерактивная, двумя способами:
  - **QR-код** (в консоли/в web-странице) → скан в мобильном приложении Telegram (удобно, если телефон уже авторизован);
  - **номер телефона + код** (код приходит в Telegram/SMS) + при необходимости пароль 2FA.
- После успешного входа Telethon сохраняет **сессию** (файл или строку), которую можно использовать повторно без повторной авторизации.

### Локальное приложение Telegram (tdata) — не переиспользуется
Сессия Telegram Desktop хранится в `tdata` в зашифрованном виде и привязана к конкретной сборке приложения; сторонние библиотеки её официально не читают. Поэтому авторизация делается через MTProto-поток (QR или телефон+код), а не через чтение tdata.

### Хранение и шифрование
- **`api_id` / `api_hash`** — не секреты уровня пароля, но храним в ConfigStore.
- **Сессия Telethon** (это и есть «токен» доступа к аккаунту) — шифруется:
  - Телефон / StringSession — сохранять в Windows Credential Manager через `keyring` (см. `app/ai/secrets.py`: `SERVICE_NAME = "comfyui-meta-viewer"`, паттерн `SystemSecretStore.get/set/delete`). `keyring` уже в зависимостях (`^25.7`), на Windows бэкенд — DPAPI/Windows Credential Manager.
  - Либо файл сессии Telethon с паролем/в каталог с ограниченными правами.
- Итоговое требование: секрет читается только тем же Windows-пользователем; в репозиторий/конфиги-json не попадает.

### Таргетинг и отправка
- «Отправить контакту из списка» → получаем контакты/диалоги (`client.get_dialogs()`, поиск по имени), выбираем `chat_id`.
- «Добавить в избранное» → Saved Messages = диалог с самим собой (`me`).
- «Опубликовать в свою группу» → `client.send_file(chat, file=..., caption=...)`; медиа с диска (оригиналы лежат локально).
- Несколько работ → `album` (группа медиа).

## Цель 2: ВКонтакте (потом)

### Токен
- Нужен **user-токен** со scope `photos,video,wall,offline` (+ `messages` для лички). Community-токен **недостаточен**: `photos.getWallUploadServer` с group auth даёт **error 27**.
- Ограничения: `wall.post` ~50/день, до 10 вложений на пост.

### Поток авторизации (браузер, без деплоя)
1. Кнопка «Авторизоваться в ВК» открывает в браузере:
   `https://oauth.vk.com/authorize?client_id=<id>&scope=photos,video,wall,offline&redirect_uri=https://oauth.vk.com/blank.html&response_type=token`
2. Пользователь входит (если ещё не авторизован) → VK редиректит на `blank.html#access_token=...&expires_in=...&user_id=...`.
3. **Перехват токена** из URL-фрагмента:
   - приложение поднимает локальный слушатель/через helper-страницу читает фрагмент и передаёт токен в приложение;
   - или (fallback) подсказка пользователю скопировать `access_token` из адресной строки и вставить в поле.
4. Валидация: `users.get` с полученным токеном (проверяем `user_id`).
5. **Шифрование токена** — тот же механизм `keyring` (Windows Credential Manager / DPAPI), что и для Telegram-сессии.

### Публикация
- Фото: `photos.getWallUploadServer?group_id=` → загрузка файла → `photos.saveWallPhoto` → attachment `photo{owner}_{id}` → `wall.post` (для группы `owner_id=-<gid>`, `from_group=1`).
- Видео: `video.save` (с `wall=1` и `group_id`) → upload_url → PUT видео → `wall.post`.
- Личка: `messages.send` с attachment'ами (фото/видео).

## Архитектура в проекте

- Новый blueprint, напр. `app/integrations/social/` (`telegram.py`, `vk.py`, `routes.py`, `secrets.py` или переиспользование `app/ai/secrets.py`).
- Роуты: `GET/POST /api/social/<provider>/status`, `/auth/start`, `/auth/token`, `/disconnect`; `POST /api/social/<provider>/publish` (ids работ + target).
- UI: карточки авторизации в настройках (образец — CLI-интеграции), кнопка экспорта в `#selection-toolbar` медиатеки (Select Mode уже есть в `library.html`).
- Секреты: только через keyring; конфиг — только несекретные поля (api_id, app_id, scope).

## Открытые вопросы / риски

- Telegram: автоматизация от личного аккаунта против правил Telegram — ограничиться **ручной** публикацией (по кнопке), без массовых рассылок.
- Telegram: подтвердить версию Telethon и совместимость с Python 3.12 в venv.
- VK: наличие/создание VK-приложения (`client_id`) и выдача scope `wall`/`messages` (для новых приложений — через поддержку или VK ID).
- Где хранить non-secret `api_id`/`api_hash` Telegram и `client_id` VK: ConfigStore + настройки UI.
