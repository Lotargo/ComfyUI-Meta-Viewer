# План перехода на SOLID-архитектуру и декомпозицию God-объектов

Этот документ представляет собой подробное руководство по рефакторингу кодовой базы проекта **ComfyUI Meta Viewer**. Цель рефакторинга — разделение крупных God-объектов на слабосвязанные специализированные пакеты и модули в соответствии с принципами **SOLID**, сохраняя при этом удобство работы и предотвращая избыточное раздувание файлов.

---

## 1. Текущие проблемы архитектуры (God-объекты)

### Frontend (Клиентская часть)
* **`app/static/js/features/workflow-editor.js` (~3900 строк):**
  Главный God-объект клиентской части. Совмещает в себе:
  - Инициализацию редактора и переключение шаблонов.
  - Управление ресурсами, LoRA и вызов рекомендаций Civitai.
  - Контроль соотношения сторон (Aspect Ratio), кастомных разрешений и шкал.
  - API-вызовы префлайта, компиляции драфтов, запуска генераций и отслеживания очередей.
  - Мастер импорта и маппинга пользовательских рабочих процессов (Import/Mapping Wizard).
  - Управление локальным процессом ComfyUI (Console, Logs, Hardware Metrics).
  - Систему генерации промптов с ИИ (AI Draft, Translate, Adapt, Reconstruct).
  - Отображение истории генераций (`resultGrid`, обработка ошибок).

### Backend (Серверная часть)
* **`app/main.py` (~1100 строк):**
  Совмещает маршрутизацию страниц, сканирование папок, работу с альбомами, вырезание объектов (cutout), системную диагностику и отдачу медиа-файлов.
* **`app/comfyui/editor_routes.py` (~1200 строк):**
  Огромная концентрация роутов управления драфтами, запусками, рекомендациями моделей и маппингом.

## 2. Применение принципов SOLID к рефакторингу

* **S - Single Responsibility Principle (Принцип единственной ответственности):**
  Каждый класс/модуль решает ровно одну задачу. Мы выделяем каждую обособленную подсистему в отдельный изолированный модуль.
* **O - Open/Closed Principle (Принцип открытости/закрытости):**
  Система должна быть расширяемой без изменения существующего кода. Например, новые ИИ-операции добавляются в виде плагинов в отдельный реестр без переписывания мастера промптов.
* **L - Liskov Substitution Principle (Принцип подстановки Лисков):**
  Все реализации интерфейсов ведут себя предсказуемо и взаимозаменяемо.
* **I - Interface Segregation Principle (Принцип разделения интерфейсов):**
  Интерфейсы взаимодействия компонентов должны быть узкими. Компоненты не должны зависеть от методов, которые они не используют.
* **D - Dependency Inversion Principle (Принцип инверсии зависимостей):**
  Модули не импортируют друг друга напрямую через жесткие связи. Вместо этого они общаются через события (на клиенте) или через абстрактные интерфейсы/сервисы (на бэкенде).

## 3. Декомпозиция Frontend: Разделение `workflow-editor.js`

Мы разделяем монолитный файл на несколько слабосвязанных модулей, находящихся в `app/static/js/features/`. Каждый модуль экспортирует класс-контроллер или функцию инициализации.

### Предлагаемая структура файлов

- [ ] `app/static/js/features/workflow-editor.js` — Фасад (Facade) / Главный координатор
- [x] `app/static/js/features/civitai-downloader.js` — Изолированный загрузчик моделей (уже сделан!)
- [ ] `app/static/js/features/aspect-ratio-controller.js` — Сетка aspect ratio, кастомные ползунки, замки соотношения сторон
- [ ] `app/static/js/features/ai-prompt-wizard.js` — Диалоги ИИ-генерации (Draft, Translate, Adapt, Reconstruct)
- [ ] `app/static/js/features/comfyui-process-manager.js` — Управление запуском ComfyUI, логи консоли, графики железа
- [ ] `app/static/js/features/mapping-wizard.js` — Импорт шаблонов JSON/ZIP, сопоставление нод
- [ ] `app/static/js/features/generation-history.js` — Сетка результатов, пагинация, поллинг состояния генерации

### Детали реализации модулей

#### 1. `aspect-ratio-controller.js` (SRP)
Отвечает только за кастомные размеры и пресеты соотношений сторон.
- [ ] Содержит обработчики кликов по сетке `[data-aspect-grid]`, управление замком `aspectRatioLock`, синхронизацию текстовых полей ширины/высоты с их ползунками (range).
- [ ] По завершении изменения размеров контроллер генерирует кастомное событие:
  ```javascript
  window.dispatchEvent(new CustomEvent('editor:resolution-changed', {
      detail: { width: normalizedWidth, height: normalizedHeight }
  }));
  ```

#### 2. `ai-prompt-wizard.js` (SRP + OCP)
Изолирует все диалоги взаимодействия с ИИ-генератором.
- [ ] Инициализирует диалоги `#ai-prompt-dialog`, `#translate-prompt-dialog`, `#adapt-prompt-dialog`, `#reconstruct-prompt-dialog`.
- [ ] Вызывает эндпоинты `/api/ai/*` и генерирует драфт.
- [ ] При создании нового драфта генерирует событие:
  ```javascript
  window.dispatchEvent(new CustomEvent('editor:draft-created', {
      detail: { draft: createdDraft }
  }));
  ```

#### 3. `comfyui-process-manager.js` (SRP)
Отвечает за одноимённый SETUP-интерфейс «Connect ComfyUI».
- [ ] Управляет отображением панели в ящике (drawer), запуском, остановкой, прерыванием (`interrupt`), загрузкой конфигурации.
- [ ] Осуществляет периодическое чтение логов консоли `/api/comfyui/logs`.

#### 4. `mapping-wizard.js` (SRP)
Управляет импортом шаблонов.
- [ ] Обработка Drag-and-drop в зоне импорта, отображение результатов анализа маппинга.
- [ ] Вывод полей редактирования метаданных и сопоставление нод ComfyUI.

#### 5. `generation-history.js` (SRP)
Выводит историю генераций и управляет очередью.
- [ ] Отображает ленту прогресса выполнения (`run-ribbon`), запускает поллинг `/api/editor/runs`.
- [ ] Формирует сетку результатов, обрабатывает ошибки загрузки картинок (с отображением плейсхолдера `.result-media-error-placeholder`) и вызывает лайтбокс.

#### 6. `workflow-editor.js` (Facade)
Главный файл-координатор. Он становится невероятно лёгким (менее 300 строк).
- [ ] Создает экземпляры всех контроллеров фич.
- [ ] Слушает кастомные события от подсистем (например, `'editor:resolution-changed'`, `'editor:draft-created'`) и обновляет глобальный `state`.
- [ ] Отвечает за общую валидацию формы редактора и отправку итоговой конфигурации в ComfyUI.

## 4. Декомпозиция Backend: Разделение маршрутов

Вместо монолитных файлов мы внедряем модульную структуру роутинга на базе Flask Blueprints.

### Предлагаемая структура файлов бэкенда

- [ ] `app/main.py` — Только запуск, регистрация Blueprints, CORS
- [ ] `app/routes/library.py` — Эндпоинты альбомов, медиабиблиотеки, тегов, favorites
- [ ] `app/routes/sources.py` — Сканирование папок, reconciling, watchdog
- [ ] `app/routes/media.py` — Отдача оригиналов, генерация thumbnails, previews
- [ ] `app/routes/cutout.py` — Автоматическое вырезание объектов (cutout)
- [ ] `app/routes/ai.py` — Профили промптов, генерация, перевод, вижн
- [ ] `app/routes/editor.py` — Драфты, запуски рабочих процессов, ComfyUI config

### Инверсия зависимостей на Бэкенде (DIP)
Каждый модуль маршрутизации не должен напрямую лезть в SQLite и писать сложные SQL-запросы в обработчиках запросов.
- [ ] Роуты делегируют работу выделенным сервисным классам (например, `WorkflowService`, `LibraryService`, `CutoutService`), которые в свою очередь общаются с базой данных через тонкий репозиторный слой.
- [ ] Маршруты становятся компактными (по 5-10 строк кода), легко читаемыми и поддающимися быстрому юнит-тестированию.

## 5. План безопасного перехода на новую архитектуру

Чтобы рефакторинг прошёл гладко, без нарушения работоспособности приложения, необходимо придерживаться **инкрементального подхода**:

- [ ] **Шаг 1: Подготовка тестов**
  - [ ] Убедиться, что все юнит-тесты на бэкенде (`poetry run pytest`) и тесты метаданных/предпочтений (`npm run test:metadata`, `npm run test:preferences`) полностью проходят. Они будут нашей страховкой.
- [ ] **Шаг 2: Выделение фич во Фронтенде (по очереди)**
  - [ ] Начать с `aspect-ratio-controller.js`. Вырезать его код из `workflow-editor.js`, перенести в отдельный модуль фичи, импортировать его и связать через шину событий. Проверить работу в браузере.
  - [ ] Повторить для `comfyui-process-manager.js`, `ai-prompt-wizard.js`, и т.д.
- [ ] **Шаг 3: Выделение Blueprints на Бэкенде**
  - [ ] Перенести роуты из `app/main.py` в пакет `app/routes/`. Каждый перенос сопровождается запуском тестов, чтобы не поломать интеграцию.
- [ ] **Шаг 4: Полноценное тестирование и замеры скорости**
  - [ ] После каждого шага запускать Playwright-сценарии для замера производительности (FP, LCP, TTI) и отслеживания ошибок консоли.

Применение этого плана позволит сделать кодовую базу **ComfyUI Meta Viewer** кристально чистой, легко расширяемой и готовой к масштабированию без риска запутаться в огромных God-объектах!
