# Create / Simple Mode — план восстановления интерфейса

## Статус документа

Этот файл больше не описывает старый Workflow Editor. Для пользовательской страницы `/create` источником продуктовых требований является `docs/simple-mode-redesign.md`.

Текущая задача — не «подкрасить» существующий экран, а привести Create к запланированной модели Simple Mode: пользователь описывает идею, при необходимости добавляет изображение, выбирает понятную модель и несколько семантических параметров, а технические детали ComfyUI остаются за интерфейсом.

---

## 1. Зафиксированные проблемы текущей реализации

### 1.1 Компоновка страницы

- На пустом экране постоянно показывается огромная правая область результата. До запуска генерации она ничего не даёт и визуально превращает Create в двухпанельный редактор.
- Основная форма слишком узкая относительно доступного пространства, поэтому контролы выглядят сжатыми и случайными.
- Иерархия не соответствует prompt-first сценарию из `docs/simple-mode-redesign.md`.
- После открытия ИИ-помощника он становится полноценной правой колонкой на всю высоту окна и ещё сильнее дробит пространство.

### 1.2 Ambient background

- Фоновая система формально реализована, но контейнер помещён на `z-index: -1`; на реальной странице ambient может оказаться за фоном документа и стать невидимым.
- Нет нормального визуального fallback-состояния, если библиотека пуста или превью не загрузилось.
- Ambient не должен заменять функциональные цвета темы. Он остаётся декоративным слоем.

### 1.3 Изображение-ориентир / reference

- В текущем состоянии превью может отображаться битым изображением.
- Контрол визуально напоминает обёртку вокруг стандартного browser file input вместо самостоятельного элемента продукта.
- Нужны проверка типа/размера, понятное удаление, drag & drop и стабильное локальное превью.
- Нативный `input[type=file]` должен оставаться скрытым механизмом выбора файла, а пользователь должен видеть кастомный контрол.

### 1.4 Prompt

- Поле должно автоматически расти вместе с текстом, но не бесконечно: нужен диапазон высоты и внутренний scroll после достижения максимума.
- AI improvement должен восприниматься как постоянный режим компиляции запроса, а не как ещё одна кнопка «магии».
- Формулировки не должны копировать лексику Шедеврума. Слово `masterpiece` также не должно оставаться fallback-текстом внутри Simple Mode backend.

### 1.5 Выбор модели

- Название секции `Режим` и карточки `Фото / Аниме / Арт` вводят в заблуждение. Это не режимы и не стили.
- В `docs/simple-mode-redesign.md` уже зафиксировано: пользователь выбирает **Модель**. `Style` зарезервирован для будущих LoRA/style adapters.
- Backend уже отдаёт богатые данные профилей: название, описание, strengths/weaknesses, VRAM, technical model, quality presets и health. Текущий UI почти не использует эти данные.
- Нужны визуальные модельные карточки с собственной графикой и вторичной подробной информацией по hover/focus, а не три одинаковых dashboard-плитки.

### 1.6 Качество и количество изображений

- Контролы `quality` и `batch` существуют в backend и входят в продуктовый план, но текущий шаблон скрывает их через `hidden` и всегда отправляет дефолтные значения.
- Качество должно оставаться семантическим (`Быстро / Обычно / Детально / Максимум`) и получать реальные параметры выбранного профиля динамически.
- Batch должен быть простым выбором 1–4 без технических терминов.

### 1.7 Иконки и визуальная идентичность

- Ключевые элементы собраны из типовых линейных SVG и визуально похожи на набор компонентов dashboard.
- Для signature controls нужны собственные SVG-глифы: модели, reference, AI improvement, Create/progress. Utility controls (`×`, тема и т.п.) могут оставаться обычными.
- Не требуется превращать весь экран в набор растровых ассетов. Кастомизация нужна там, где она формирует характер продукта.

### 1.8 ComfyUI status

- Технический бейдж `ComfyUI` не нужен на основной странице создания.
- Даже при корректной health-проверке он заставляет пользователя думать о runtime, который Simple Mode как раз должен скрывать.
- Ошибки подключения показываются только тогда, когда они реально мешают действию, в человекочитаемом repair/error состоянии с техническими деталями по запросу.

### 1.9 ИИ-помощник

- Помощник не должен постоянно занимать целую правую часть приложения.
- Нужен отдельный сфокусированный floating panel / modal с backdrop, который открывается поверх Create и не меняет основную геометрию страницы.
- Кнопка `Новый диалог` в текущей реализации присутствует визуально, но должна реально очищать историю.
- Нужны Escape/backdrop close, нормальный многострочный input и быстрые контекстные действия.

### 1.10 Профильные примеры

- Backend содержит `image_url` для примеров моделей, но соответствующий `app/static/assets/examples` сейчас не является надёжной частью поставки.
- Пока реальные отобранные примеры не добавлены, UI не должен строиться вокруг несуществующих картинок или показывать broken images.
- Галерею примеров подключать только после добавления реальных ассетов.

## 2. Целевая структура Create

### Idle

```text
Header

                 ┌───────────────────────────────────┐
                 │ CREATE                            │
                 │ Что создаём?                      │
                 │                                   │
                 │ [ большой auto-grow prompt ]      │
                 │ [image]              [AI improve] │
                 │                                   │
                 │ Модель                            │
                 │ [Realism] [Anime] [Universal]     │
                 │                                   │
                 │ Соотношение сторон                │
                 │ [1:1] [3:4] [4:3] [9:16] [16:9]  │
                 │                                   │
                 │ Качество             Изображений  │
                 │ [semantic presets]       [1 2 3 4] │
                 │                                   │
                 │             [ Создать ]           │
                 └───────────────────────────────────┘
```

До запуска генерации отдельный пустой canvas не показывается.

### Generating / Result

После `Создать` layout мягко раскрывается в две области:

```text
┌──────── controls ────────┐  ┌──────── result ──────────┐
│ исходные параметры       │  │ progress / image         │
│ можно видеть контекст    │  │ actions                  │
└──────────────────────────┘  └──────────────────────────┘
```

Это даёт пространству результата смысл только тогда, когда результат действительно существует или создаётся.

## 3. План реализации

### Этап A — P0: восстановить базовый UX

1. Исправить stacking ambient слоя и добавить fallback background.
2. Перестроить `/create` в prompt-first single-surface idle layout.
3. Показывать result stage только в `generating/result` состояниях.
4. Удалить пользовательский ComfyUI status badge.
5. Переименовать `Режим` в `Модель` и убрать `Фото / Арт` как псевдокатегории.
6. Вернуть видимые Quality и Batch controls.
7. Починить reference preview и полностью скрыть browser file input.
8. Ограничить auto-grow prompt разумной максимальной высотой.
9. Исправить работу `Новый диалог` у AI assistant.
10. Удалить `masterpiece` из backend fallback Simple Mode.

### Этап B — визуальная система

1. Добавить собственные SVG-глифы для трёх модельных профилей.
2. Добавить отдельные глифы для reference, AI improvement и Create.
3. Сделать карточки моделей визуально различимыми, но не «баннерами».
4. Добавить компактные hover/focus details: сильные стороны, VRAM, technical model.
5. Привести motion к одной системе timings и easing.

### Этап C — модельные данные и состояния

1. Использовать `profile.health` и не притворяться, что профиль готов, если он требует настройки.
2. Подставлять steps/metadata в Quality UI из `profile.quality_presets`.
3. Отключать неподдерживаемые aspect ratios/quality options на основе активного профиля.
4. Не показывать отсутствующие profile example assets до появления реальных файлов.

### Этап D — assistant

1. Floating panel вместо full-height layout column.
2. Backdrop + Escape close.
3. Рабочий New conversation.
4. Многострочный input с auto-grow.
5. `Apply prompt` остаётся явным действием пользователя.
6. Ассистент не должен блокировать обычный happy path и не должен быть обязательным для генерации.

### Этап E — проверка

Проверить минимум:

- `/create` без изображений в библиотеке;
- `/create` с ambient candidates;
- reference PNG/JPEG/WebP;
- удаление reference и повторное добавление другого файла;
- длинный prompt;
- AI improvement on/off + persistence;
- все три модели;
- все aspect ratios;
- все quality presets;
- batch 1–4;
- generating → completed;
- generating → failed;
- assistant open/close/new chat/apply;
- Dark / Light / Strawberry themes;
- desktop 1920/1440/1280 и mobile presentation;
- reduced-motion.

## 4. Acceptance criteria

- [ ] На idle экране нет бессмысленного пустого canvas.
- [ ] Ambient фон реально виден и корректно работает без изображений библиотеки.
- [ ] Нет нативного `Выберите файл` / browser upload UI.
- [ ] Reference preview не показывает broken-image состояние при корректном локальном файле.
- [ ] Prompt плавно растёт до максимальной высоты, затем скроллится внутри.
- [ ] Основной selector подписан `Модель`, не `Режим` и не `Стиль`.
- [ ] Model cards используют реальные backend profiles и их metadata.
- [ ] Видны Quality и Images/Batch controls.
- [ ] Ключевые controls имеют собственную визуальную графику, а не только generic icon set.
- [ ] ComfyUI connection badge отсутствует в Simple Mode UI.
- [ ] Ошибка runtime появляется только при реальной проблеме и объясняется человеческим языком.
- [ ] `Новый диалог` у assistant действительно сбрасывает conversation state.
- [ ] Assistant открывается поверх Create, а не отнимает постоянную колонку.
- [ ] В Simple Mode UI/backend нет лексики `masterpiece/шедевр` как продуктового обозначения или fallback prompt.
- [ ] Результат появляется в отдельной области только после старта генерации.
- [ ] Существующие Simple Mode API contracts сохраняются.

---

## 5. Что сейчас намеренно не делаем

В этот рефакторинг не входят arbitrary workflow import, node editor, ControlNet, IP-Adapter, LoRA browser, advanced sampler controls и другие функции будущего Advanced Mode.

Не нужно снова превращать Create в упрощённую копию ComfyUI. Чем больше технических подробностей просачивается в основной happy path, тем дальше интерфейс уходит от цели Simple Mode.
