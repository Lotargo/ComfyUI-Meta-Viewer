# v1 Release Plan

Этот файл содержит только задачи, которые действительно нужны для первого публичного релиза ComfyUI Meta Viewer.

Архитектурные документы в этой директории остаются источником идей и требований для дальнейших версий, но не превращаются в обязательные сотни подпунктов перед v1.

## Цель релиза

Пользователь должен суметь установить приложение, добавить папку с результатами ComfyUI, открыть медиа и метаданные, использовать базовую библиотеку и выполнить хотя бы один полный сценарий генерации через подключённый ComfyUI.

## Обязательные задачи

- [ ] `poetry install --no-root` и тесты проходят в текущей CI-матрице Windows, Linux и macOS.
- [ ] Приложение запускается из чистого окружения, открывает главную страницу и индексирует выбранную папку.
- [ ] Изображение и видео открываются без критической ошибки; основные метаданные и preview доступны.
- [ ] Альбом, избранное или другая базовая виртуальная операция сохраняется после перезапуска приложения.
- [ ] Один встроенный workflow проходит полный путь: выбор ресурсов → отправка в ComfyUI → получение и импорт результата.
- [ ] README содержит актуальную установку, запуск, минимальный пример и честный список известных ограничений; после этого создаётся тег релиза.

## Что не блокирует v1

Следующие работы выполняются после релиза или только при обнаружении реальной проблемы:

- проверка каждого сочетания ОС, файловой системы, Unicode, UNC и облачного клиента;
- длительные stress tests watcher, reconnect и массовой синхронизации;
- поддержка всех loader families, GGUF-вариантов и custom nodes;
- универсальный импорт и автоматическое распознавание любого workflow;
- полный набор Generate, Translate, Adapt, Reconstruct и Remix для каждого семейства моделей;
- исчерпывающие prompt benchmarks и повторные платные provider calls;
- AI rating;
- desktop installers, auto-update и подпись пакетов.

## Правило остановки

Новый пункт добавляется в обязательный список только тогда, когда найден конкретный дефект, мешающий установке, запуску, сохранности данных или основному пользовательскому сценарию.

Улучшение качества, дополнительная совместимость или редкий edge case записываются в backlog и не задерживают релиз автоматически.

## Решение о выпуске

После закрытия шести обязательных пунктов выпускается v1 с известными ограничениями. Не требуется доказывать идеальную работу всех будущих функций до публикации первой версии.
